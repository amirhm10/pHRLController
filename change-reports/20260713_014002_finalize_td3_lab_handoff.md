## Method and implementation summary

The existing fixed filenames in `main.py` already select the bundled model, so
no BioSMB interaction code or `main.py` logic was changed. The selected
manifest, actor weights, training checkpoint, and training configuration were
treated as one immutable set. Their source is
`offline_ph_td3_training_20260710_183129`, policy ID
`custom_td3_0c10ce7b8602bd5c`, and saved rollout length 500000 steps.

For future offline runs, the TD3 target now again uses

$$
y_t = r_t + 0.97(1-d_t)\min_{i\in\{1,2\}} Q_{\theta_i'}
\left(s_{t+1}, \tilde{a}_{t+1}\right).
$$

The online settings remain separate: batch size `64`, replay capacity `10000`,
recent sampling window `200`, and exploration noise `0.02 -> 0.01`.

## Known limitations and next steps

- The selected policy is simulation-trained and is not physically lab
  validated.
- Docker is not installed/running on this computer, so the final image build,
  `docker compose config`, and in-container actor/trainer preflight remain for a
  Docker-enabled computer.
- The checkpoint was produced with Python 3.13.7 whereas the retained reference
  Docker base is Python 3.11. Hash and inference checks reduce this risk but do
  not replace the in-container preflight.
- No live Redis, MongoDB, MFCS, OPC UA, sensor, or pump test was possible.
- An existing Docker `models` volume can hide model files bundled in a newly
  built image; the lab must verify the four files and hashes in the mounted
  volume before startup.
- The legacy `.pkl` contains model and target weights but not replay, optimizer,
  or RNG state. Online learning therefore begins with the pretrained networks,
  fresh optimizers, and an empty online replay buffer.
- Commissioning must follow the staged checklist in
  `Biosmb-run-online/Biosmb-run-online/TD3_LAB_HANDOFF_REPORT.md` before active
  lab control is approved.
